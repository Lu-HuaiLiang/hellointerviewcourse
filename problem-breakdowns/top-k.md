热门榜先要数对每个对象的完整频率，再讨论怎样选出前K名。

## 遇见问题 · 先从一个具体场景开始

按最近十分钟观看次数选出热门视频。事件可能重复或迟到；明确本课要求精确计数，先不使用近似草图。


## 概念原理 · 先把概念讲清楚

- **局部Top K**：某个分区内按计数选出的前K个对象，是否能合并取决于分区方式。
- **事件时间窗口**：按发生时间统计的有限范围，需要定义迟到、去重和窗口边界。


若每个视频的全部计数只属于一个分区，那么全局Top K一定能从各分区Top K的并集中找到：没进本片前K的对象，在本片已有至少K个对象不比它差。这个推理依赖每个对象计数完整，以及一致的并列排序规则，不能直接用于同一视频被随机拆散的事件分片。


事件先按稳定身份去重，再按video_id归组计算窗口频率。局部聚合之后选候选，合并时统一排序。热点视频可能需要先打散局部计数，但此时必须先按视频再次求和，再选Top K；不能在碎片仍未汇总时丢弃局部未进榜对象。

## 具体例子 · 用一个例子，把因果连起来

### 从条件推到结果

K=1，分片一有A=6、X=5，分片二有B=6、X=5。分别只保留冠军A和B，就永远看不到全局X=10。反例说明随机事件分片上的局部冠军不够。若按视频键归组，X的10次属于同一片，再取局部冠军才满足完整计数前提。

### 需求边界：先定义哪个问题？

**备选：先挑一个堆的数据结构**

堆无法弥补统计口径不明。

路径：未定义事件 → 堆 → 含糊排名

**基线：窗口与去重口径**

计数窗口、有效观看与重复事件定义清楚，排名才有业务意义。

路径：观看定义 → 窗口 → 计数

### 实体与接口：事件应有什么身份？

**基线：稳定event_id与发生时间**

稳定身份可去重，发生时间用于事件时间窗口，避免延迟导致错窗。

路径：event_id＋事件时间 → 去重 → 分窗

**备选：仅服务器收到时的序号**

接收序号不能识别重投，也不表达实际观看时间。

路径：接收顺序 → 错误分窗 → 重复计数

### 基础架构：怎样聚合每个视频？

**备选：每个事件随机分散后直接排名**

随机分散后一个视频被拆成多份，必须再次按键汇总。

路径：随机事件分片 → 碎片计数 → 排名失真

**基线：按video_id分区累加窗口**

同一视频汇聚到负责分区，能得到该视频完整计数。

路径：视频键 → 分区计数 → 完整频率

### 扩展瓶颈：何时可以合并局部Top K？

**基线：每个视频完整计数只属于一片**

键互斥分区下，全局前K必在局部前K并集中；同键碎片则不成立。

路径：键分区Top K → 候选并集 → 全局Top K

**备选：各片包含同一视频的零散计数**

局部未进榜的碎片合计后可能是全局热门，直接合并会漏掉。

路径：碎片Top K → 遗漏候选 → 错误全局榜

### 故障处理：迟到和重复观看怎么处理？

**备选：收到一次就永远加一**

网络重试会抬高计数，迟到会把窗口统计弄乱。

路径：所有投递 → 直接加一 → 重复与错窗

**基线：去重并定义允许迟到与修正**

窗口需迟到策略与状态保留，重投按身份去重，超出时限按约定处理。

路径：事件校验 → 窗口修正 → 更新排名


## 适用边界 · 什么时候，需要重新考虑

窗口计数还会受重复和迟到影响。即时榜可以允许修正，但应规定冻结时机。近似草图能节省空间，却改变精度承诺，本课基线要求精确，因此不能悄悄把估计数当作真实次数。


**本场景下的扩展方向**

每个视频完整计数只属于一片。键互斥分区下，全局前K必在局部前K并集中；同键碎片则不成立。

**另一条路径与它的代价**

各片包含同一视频的零散计数。局部未进榜的碎片合计后可能是全局热门，直接合并会漏掉。


## 带走结论 · 把这几个想法，带走

- Top K先是计数问题，再是选前K问题。
- 局部Top K合并的正确性依赖分区方式。
- 窗口、去重与迟到策略决定排名含义。
