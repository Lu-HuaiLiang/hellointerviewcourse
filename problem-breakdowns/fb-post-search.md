搜索结果是候选集合，最终可见内容还必须遵守权限与删除状态。

## 遇见问题 · 先从一个具体场景开始

按关键词搜索帖子，并尊重好友可见、删除和屏蔽关系。新帖允许短暂索引延迟，权限撤销不能只等缓存自然过期。


## 概念原理 · 先把概念讲清楚

- **候选检索**：按关键词或相关性从索引中找可能匹配的文档，尚未完成全部业务过滤。
- **权限后验**：在返回候选前再次检查当前访问资格，避免陈旧索引暴露内容。


帖子搜索通常以倒排索引支持词项查询，主存储保留帖子与权限事实。新帖可以异步进入索引，读者短时间搜不到可能可接受；但隐私撤销后的旧内容继续可见，往往需要更严格处理。不同变化可以有不同新鲜度承诺，不能用一个统一TTL解决所有问题。


数据库变化通过事件或CDC更新索引，携带版本防止旧更新覆盖新状态。候选返回前校验可见性、删除和屏蔽关系，再取正文。过滤会减少一页结果，需要继续取候选直到足够或到达上限，同时避免无界检索。搜索排序与授权规则应各自清晰。

## 具体例子 · 用一个例子，把因果连起来

### 从条件推到结果

帖子P原本公开，作者改成仅好友可见，但索引仍记着公开。陌生人查询命中P，若直接返回索引全文就会泄露；按当前权限过滤后应隐藏。搜索标题、摘要甚至总命中数也可能暴露信息，敏感场景需一起考虑展示边界。

### 需求边界：除相关性外，最先保证什么？

**备选：只要关键词匹配就返回**

索引命中不证明请求者有权看到原文。

路径：关键词匹配 → 直接输出 → 私密内容泄漏

**基线：结果可见性与删除语义**

搜索也是访问内容的路径，必须跟随权限边界。

路径：关键词候选 → 权限过滤 → 可见结果

### 实体与接口：用哪类索引找关键词？

**基线：倒排索引与文档标识**

词项映射到候选帖子，再排序和过滤。

路径：词项 → 帖子ID集合 → 候选

**备选：只靠帖子主键哈希**

主键哈希适合按ID定位，不适合包含某词的搜索。

路径：关键词 → 主键哈希 → 无法按词定位

### 基础架构：数据库变化怎样进索引？

**备选：业务接口先索引再写库且不恢复**

双写中途失败会留下不存在或缺失的帖子。

路径：先写索引 → 数据库失败 → 幽灵帖子

**基线：持久变更流异步更新**

把数据库作为事实来源，记录可靠变更并幂等更新索引。

路径：帖子数据库 → CDC或Outbox → 搜索索引

### 扩展瓶颈：查询范围很大怎样减少工作？

**基线：分片候选、局部排序再合并**

分布式候选检索减少单点工作；最终排序与权限过滤仍需处理。

路径：索引分片 → 候选Top集合 → 合并过滤

**备选：把所有原文送到一个进程排序**

全量原文搬运增加网络和内存成本。

路径：所有原文 → 单机排序 → 内存压力

### 故障处理：用户删帖，索引还没追上？

**备选：等索引定期刷新即可**

只等刷新可能在窗口期继续展示已撤回内容。

路径：旧索引 → 直接展示 → 撤回失效

**基线：最终读取核对删除或撤权状态**

关键可见性需要可靠拦截路径，派生索引可稍后清理。

路径：候选帖子 → 最新可见性检查 → 过滤


## 适用边界 · 什么时候，需要重新考虑

全量扫描帖子表不适合一般全文检索，缓存结果也不能永久绕过权限校验。删除事件和索引重建要保持版本顺序。这里用关键词搜索解释检索与授权分层，不假定某公司的内部权限实现。


**本场景下的扩展方向**

分片候选、局部排序再合并。分布式候选检索减少单点工作；最终排序与权限过滤仍需处理。

**另一条路径与它的代价**

把所有原文送到一个进程排序。全量原文搬运增加网络和内存成本。


## 带走结论 · 把这几个想法，带走

- 倒排索引解决候选查找，权限判断解决可见性。
- 数据库事实与搜索派生视图通过可靠变更衔接。
- 搜索新鲜度与权限撤销是不同承诺。
