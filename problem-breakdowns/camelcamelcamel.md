价格观察包含来源、时间和有效性，缺失数据不能当成零价格。

## 遇见问题 · 先从一个具体场景开始

定期观察商品价格并在低于用户阈值时通知。商品很多，商家有速率限制，抓取失败与真实价格变化要区分。


## 概念原理 · 先把概念讲清楚

- **价格观测**：在特定时间从特定来源得到的一次有效价格记录，包含币种与规格语义。
- **阈值穿越**：价格从阈值上方变到下方的状态变化，可用于减少重复提醒。


追踪系统先维护商品与抓取计划，再保存价格时间序列，最后评估用户提醒。商品URL变化、规格差异、折扣与币种都会改变价格含义。采集失败应记录缺失或错误，不应把解析为空转换成0，否则会制造虚假的巨大降价。


抓取频率在新鲜度与资源成本之间权衡，按站点限速并隔离失败。有效观测按时间追加，重复批次可去重。提醒系统保存上次通知状态或触发事件身份，价格长期低于阈值时不必每次采样都发消息；再次涨回再降价如何提醒则由规则明确。

## 具体例子 · 用一个例子，把因果连起来

### 从条件推到结果

目标价100，观测依次为120、抓取失败、95、95。正确行为是失败不更新有效价格，首次95触发提醒，第二次95按去重规则不重复。若把失败视为0，用户先收到假降价，后续真正降到95又可能被错误状态抑制。

### 需求边界：首要定义哪种更新承诺？

**备选：每一瞬间价格都绝对实时**

周期抓取不可能保证捕获每个瞬时变化。

路径：周期抓取 → 宣称实时 → 遗漏短时价格

**基线：周期观察，有明确采样间隔**

采样服务只能报告观测值，需要向用户说明时间与来源。

路径：定时采样 → 价格观测 → 变化检测

### 实体与接口：价格点应包含什么？

**基线：值、币种、时间、来源与状态**

币种与有效性防止误比较；金额用明确精度，失败不是零价格。

路径：价格＋币种＋状态 → 时间序列 → 可比较值

**备选：只保存一个浮点数字**

无单位和状态的数字容易制造假降价。

路径：单个数字 → 单位未知 → 错误比较

### 基础架构：如何跟踪大量商品？

**备选：每个关注者独立抓同一商品**

十万人关注一个商品会造成十万份重复工作。

路径：每个关注者 → 重复抓取 → 来源超载

**基线：按来源限速的任务队列**

同商品共享采样结果，再匹配关注者，减少重复抓取。

路径：商品采样队列 → 一次观测 → 多关注者

### 扩展瓶颈：所有商品都同频率抓取吗？

**基线：按热度和变化率分配预算**

在来源配额内优先高价值商品，同时保留最低覆盖与公平性。

路径：采样预算 → 优先级调度 → 覆盖与新鲜度

**备选：全部使用最高频率**

全量最高频会超出配额且浪费在长期不变商品上。

路径：全量高频 → 配额耗尽 → 大面积失败

### 故障处理：同次降价被多次观测怎么通知？

**备选：每次低于阈值都发一封**

重复观测会形成通知轰炸。

路径：持续低价 → 每次发送 → 重复通知

**基线：按阈值穿越与稳定告警ID去重**

记录告警状态，真正再次穿越或新价格事件才按规则提醒。

路径：新价格 → 穿越判断 → 一次告警


## 适用边界 · 什么时候，需要重新考虑

历史最低价依赖观测覆盖，不能保证没有错过两次采样之间的短暂变化。促销组合与不同规格也不能混算。提醒应链接原商品供用户确认当前价格，而不是把旧观测当即时成交承诺。


**本场景下的扩展方向**

按热度和变化率分配预算。在来源配额内优先高价值商品，同时保留最低覆盖与公平性。

**另一条路径与它的代价**

全部使用最高频率。全量最高频会超出配额且浪费在长期不变商品上。


## 带走结论 · 把这几个想法，带走

- 观测时间、币种和有效性使价格可解释。
- 以商品共享采集，再匹配多个关注者。
- 阈值穿越和幂等告警防止重复提醒。
