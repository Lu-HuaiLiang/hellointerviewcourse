爬虫的核心是有边界的调度与去重，网络请求只是执行阶段。

## 遇见问题 · 先从一个具体场景开始

从种子URL抓取公开网页并发现新链接。网页会重复指向彼此，部分站点很慢；抓取必须遵守站点规则并限制访问频率。


## 概念原理 · 先把概念讲清楚

- **Frontier**：等待抓取的URL集合与调度状态，决定下一步可抓什么。
- **主机礼貌策略**：按目标站点控制访问间隔、并发与规则，避免集中请求造成过载。


网页会互相循环链接，也可能生成无穷参数组合。爬虫需要先限定范围，规范化确定无意义的URL差异，维护已见集合，再进入主机调度。规则与速率是调度输入，不应等抓完之后才检查。发现链接不等于立即有权或有容量抓取它。


将URL按主机组织队列，可以根据每个主机下一次允许访问时间领取任务。全局Worker池还要有超时与隔离，防止慢站点占满资源。下载结果与任务状态持久化，领取采用租约；进程崩溃后可重投，并依据URL、版本或抓取批次去重。

## 具体例子 · 用一个例子，把因果连起来

### 从条件推到结果

A页面链接B，B又链接A，同时A带多个无意义片段地址。若不规范化与去重，就会无限重复；若一律删除查询参数，又可能把真正不同页面合并。先保留影响资源语义的部分，只去掉确认无关的差异，再按主机速率安排抓取。

### 需求边界：先明确哪条抓取边界？

**备选：先尽可能同时请求所有站点**

无界并发会产生重复工作并压垮目标或自己。

路径：所有链接 → 无限并发 → 拥塞

**基线：允许范围、robots与站点速率**

边界与礼貌策略是调度输入，避免无限扩张和给站点施加过载。

路径：种子 → 范围与策略 → 抓取队列

### 实体与接口：同一URL有多个写法怎么办？

**基线：谨慎规范化并持久去重**

去除确定无意义差异，再按规范键去重；查询参数可能影响内容，不能全删。

路径：URL规范化 → 已见集合 → 新任务

**备选：见到字符串就当新页面**

片段或跟踪参数可制造大量重复，但过度规范化也会合并不同页面。

路径：多种写法 → 重复任务 → 重复下载

### 基础架构：队列怎样组织更合适？

**备选：所有URL随机无节制拉取**

单个热门域名可能被大量Worker同时请求。

路径：随机拉取 → 集中同域 → 访问洪峰

**基线：按主机维护礼貌调度**

主机队列记录下一次允许访问时间，Worker只领取符合策略的任务。

路径：主机队列 → 到期可抓取 → Worker

### 扩展瓶颈：慢站点会影响其他站点吗？

**基线：隔离主机并限制超时并发**

按主机和全局配额隔离，避免慢域名耗尽全部执行资源。

路径：慢域名配额 → 隔离等待 → 其他域名继续

**备选：让所有Worker一直等它**

无限等待会让正常站点也无法推进。

路径：慢站点 → 占满Worker → 全局停滞

### 故障处理：Worker下载后崩溃如何恢复？

**备选：领取后永久删除队列项**

领取即删会让崩溃窗口里的页面永远漏抓。

路径：删除队列项 → 崩溃 → 遗漏页面

**基线：租约重投、结果按URL版本去重**

持久任务状态支持重新领取，重复抓取按版本与时间策略处理。

路径：租约超时 → 重投 → 幂等存储


## 适用边界 · 什么时候，需要重新考虑

Bloom Filter可以减少精确集合查询，但假阳性可能导致漏抓，应按覆盖目标决定是否确认。robots与允许范围要实际检查，不能把页面公开等同于可无限访问。重抓周期也应考虑变化频率和预算。


**本场景下的扩展方向**

隔离主机并限制超时并发。按主机和全局配额隔离，避免慢域名耗尽全部执行资源。

**另一条路径与它的代价**

让所有Worker一直等它。无限等待会让正常站点也无法推进。


## 带走结论 · 把这几个想法，带走

- 抓取策略、去重、主机调度和解析组成闭环。
- URL规范化需要尊重资源语义。
- 限定范围与速率，避免循环链接和慢站点拖垮系统。
